Redirection Rules Documentation

This guide details how to configure the Source and Destination fields in your redirection dashboard. Our engine supports powerful logic, variables, and pattern matching.

1. The Source Field

The Source determines when a rule triggers based on the incoming request path.

Allowed Formats:

Type Syntax Example Description
Exact Match /path /contact Matches the path exactly.
Wildcard * * Matches EVERYTHING. Use with caution as a fallback.
Regex /regex/flags /^\/blog\/([0-9]+)$/i Advanced pattern matching using Regular Expressions.
Capture groups (e.g., $1) can be used in the destination.

2. The Destination Field

The Destination determines where the user is sent. It supports static URLs, dynamic variables, and logical conditions.

A. Variables & Placeholders

You can inject request data into the destination URL using {variable} syntax.

  • {path} - The path (excluding leading slash).
  • {domain.subdomain} - The subdomain (e.g., "app" from app.example.com).
  • {query.paramName} - Value of a query string parameter.
  • {segments.0}, {segments.1} - Path segments (split by /).
  • {geo.country} - Two-letter country code (e.g., US, DE).
  • {random} - A random integer.

Modifiers (Pipes)

You can transform variables using the modifier syntax: {variable:modifier}.

  • {query.q:url_encode}
  • {path:to_lower_case}
  • {path:to_upper_case}

B. Conditional Logic

You can create dynamic destinations using the conditional syntax:

(Condition) ? True_Destination : False_Destination

Supported Operators:

  • ==, != (Equality)
  • >, <, >=, <= (Numeric/Date comparison)
  • includes (String contains)
  • ~= (Regex match, e.g., '{path}' ~= /^api/)

Time Functions:

  • time() - Current timestamp.
  • datetime('YYYY-MM-DD', 'Timezone') - Specific date timestamp.

3. Examples

Example 1: Time-Based Routing (Maintenance Mode)

Goal: Send users to a maintenance page after a specific date.

Logic:

(time() > datetime('2024-05-01', 'UTC')) ? /maintenance : /app

Example 2: A/B Testing

Goal: Split traffic 50/50 between version 1 and version 2.

Logic:

('{random}' > 500000) ? /v2/landing : /v1/landing

Example 3: API Versioning based on Path

Goal: If path contains "api", check date for v2, otherwise go to static.

Logic:

('{path}' includes 'api')
  ? (time() > datetime('2024-01-01') ? /api/v2 : /api/v1)
  : /static-content

4. Safety & Limitations (Do's and Don'ts)

⛔ What NOT to do

  • Do NOT create infinite loops: Avoid setting a destination that matches the source rule without changing the path (e.g., Source: /a, Destination: /a).
  • Do NOT nest too deeply: While we support nested logic (A ? (B ? C : D) : E), keep it under 5 levels for readability and performance. Max depth is capped at 32.
  • Do NOT use "Evil Regex": When using Regex in Source or Logic, avoid patterns that require catastrophic backtracking (e.g., (a+)+).

✅ Best Practices

  • Use quotes: Always wrap string values in logic with quotes. '{path}' == 'home'.
  • Test order: Rules are evaluated by Priority (High to Low), then Creation Date.
  • Use Groups: Use parentheses (...) to group logic clearly.
