Match modes explained
Query rules come from the ?... part of the Source field.
Path exact: /v1 matches only /v1
Path prefix: /v1 matches /v1/users (but not /v11)
Query exact: /v1?333=1 matches only the same query
Query subset: /v1?333=1 also matches /v1?333=1&x=2
Query ignore: /v1 matches /v1?anything=1
Match examples
Exact path /pricing
Catch-all *
Regex capture groups ($1, $2, ...) Source: /^\/go\/([^/]+)\/([^/]+)$/ Request: /go/docs/api Destination: https://docs.example.com/target/$1/$2 → https://docs.example.com/target/docs/api Works only when Source is a regex. $1 is the first capture group, $2 is the second.
Canonical host: www to apex (keep path + query) Source: /^\/(.*)$/ Destination: https://{{ '{' }}domain.extension{{ '}' }}/$1 Request: https://www.example.com/pricing?ref=ad -> https://example.com/pricing?ref=ad Keep Query match as Exact (or Subset). Ignore query will drop query from $1 for regex rules. Apply this rule on source hosts that start with www..
Segments indexing (no regex) Source: /go/docs Request: /go/docs Destination: https://docs.example.com/target/{{ '{' }}segments.1{{ '}' }} → https://docs.example.com/target/docs
Query forwarding Source: /go Destination: https://target.com?ref={{ '{' }}query.ref{{ '}' }}
