Migration example

Moving from HelpScout on support.example.com to Mintlify on docs.example.com? Start with a global rule, then refine with one-to-one article mappings for high-value pages.

Global path-preserving rule: source: /^\/(.*)$/
destination: https://docs.example.com/$1
One-to-one rule: source: /old-kb/slack-guide
destination: https://docs.example.com/integrations/slack
Variables + prefix rule: source: /articles (pathMatch: prefix)
destination: https://docs.example.com/integrations/articles/{{ '{' }}segments.2{{ '}' }}
Transformation Logic:
request: /articles/integrations/slack-guide
result:  /integrations/articles/slack-guide

The system indexes path segments starting from 0.
Segment [0] is articles, [1] is integrations, and [2] is slack-guide.

Canonical host example

If users type www.example.com but you want example.com, create one regex rule on your www source domains and keep query matching set to exact (or subset) so path and query are preserved end-to-end.

source: /^\/(.*)$/
destination: https://{{ '{' }}domain.extension{{ '}' }}/$1
